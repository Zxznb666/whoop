## 1. 背景与目标

### 1.1 为什么做
- WHOOP 的价值在于**解读层**：每天早上告诉你身体准备好了没有，今天该练多狠，今晚该睡多久。
- Apple Watch S10 的传感器已经能覆盖 WHOOP 的大部分输入，但 Apple 自己只给原始指标（Vitals、睡眠分期），**不给可执行的决策**。
- 自用场景不需要考虑商业化和合规上架，可以把精力全部放在算法质量和体验上。

### 1.2 目标
1. 每天醒来 5 分钟内，自动给出当天的恢复分数和负荷建议。
2. 每个分数都能回答“为什么是这个数”。
3. 通过日志和相关性分析，找出影响我恢复的行为（比如喝酒、晚饭吃得晚、咖啡因）。
4. 打开 App 首屏不超过 1 秒（读缓存），数据变动后在后台增量更新。

### 1.3 非目标
- 不做社交、团队、排行榜。
- 不做医疗诊断，所有“异常”只是提示。
- 不支持非 Apple Watch 的设备。
- 不做云端账号和多设备同步（备份除外，见 §9.4）。

### 2.2 三个关键约束与对策

**约束 A：HRV 只有零星的 1 分钟窗口**
- 对策 1（默认）：取睡眠时段内的全部 heartbeat series，每段单独清洗伪迹、计算 RMSSD，再按质量、夜间位置和睡眠分期加权，得到当晚的 HRV（见 §5.3）。
- 对策 2（可选“精准晨测”）：起床后在手表上做 1 分钟“正念 · 呼吸”，Apple 会额外生成一段静息状态下的高质量逐拍序列。App 在醒来后推送提醒。晨测和夜间测量**分别建立基线**，两者都有时按质量合成 z-score（见 §5.3.5）。
- 对策 3（兜底）：当晚没有 heartbeat series 时，退回使用 SDNN，并用 SDNN 自己的基线计算 z-score（不和 RMSSD 混算），同时把数据质量标为“低”。

**约束 B：日常心率不连续 → 负荷被低估**
- 运动时段：用 workout 期间的高频心率，结果精确。
- 非运动时段：间隔不超过 15 分钟的心率点做线性插值；超过 15 分钟的空窗，用“活动能量 → 心率”的个人回归模型估算（M3），估不出来就按静息水平处理，对负荷贡献约等于 0。
- 手表端“训练模式”：在我们自己的 watch App 里开 `HKWorkoutSession`，实时拿到每几秒一次的心率，同时显示实时负荷（见 §6.8）。

**约束 C：手表需要充电**
- 引导养成固定充电时段（建议洗澡或早晨），App 里标出“未佩戴时段”。
- 夜间没戴表时不出恢复分数，显示“昨晚未佩戴”，绝不瞎估。

### 2.3 设置前置条件（Onboarding 检查清单）
1. HealthKit 读取权限（§2.1 中的全部类型）+ 写入权限（只写正念记录，晨测用）。
2. 手表开启睡眠追踪和睡眠专注模式的作息计划。
3. 手表开启手腕检测、血氧测量、后台心率。
4. 填写或确认生日、性别（优先从 HealthKit 读取）。
5. 导入历史数据（默认 180 天，可选全部）。

## 3. 核心概念

### 3.1 生理周期（Cycle）——“一天”的定义
沿用 WHOOP 的思路：**一个周期 = 本次入睡 → 下次入睡**，而不是按自然日 0 点切分。
- 恢复分数归属于“醒来”的那个周期，在该周期开始时产出。
- 负荷从醒来开始累积，到下一次主睡眠入睡时封存。
- 小睡（时长 < 3 小时，或不在主睡眠窗口内）不切分周期，只计入睡眠需求的抵扣。
- 凌晨 1 点还没睡时，界面上仍属于“昨天”的周期；标题显示周期起始日期。
- 跨时区：周期按实际时间戳切分，展示时使用当地时间。

### 3.2 个人基线（Baseline）
- 所有分数都基于“偏离个人基线的程度”，不和人群比较。
- 每个指标维护一个**稳健基线**：第 N 晚之前最近 30 个有效夜晚的中位数 + MAD（换算成 σ = 1.4826 × MAD），并设 σ 下限；HRV 取对数 ln(RMSSD) 后统计。
- 有效夜数少于 4 晚时为“校准期”，显示分数但标注“基线建立中”；不足 30 晚时向人群先验收缩。有历史数据时，首次导入后立即可用。
- 确认生病的夜晚和跨时区旅行的头 2 晚自动从基线中剔除；饮酒、熬夜等行为夜**不剔除**。
- 完整规则见 §5.6。

### 3.3 数据质量（Confidence）
每个夜晚、每个周期都计算一个 0–1 的质量分，映射为高 / 中 / 低。依据包括：有效 HRV 段数及段间离散度、睡眠期心率覆盖率、佩戴覆盖率、生命体征完整度、是否有晨测。界面上用小圆点表示，点开能看到原因。计算方式见 §5.7。

## 5. 算法规格

> 所有算法放在独立的 Swift Package `VigorScoring` 中，实现为纯函数、配完整单元测试；参数集中放在 `ScoringConfig` 里，带版本号。下文给出的是**初始参数**，需要用自己的数据校准（见 §5.14）。

### 5.0 处理流水线与设计原则

```
HealthKit 原始样本
  │ ① 拼装与清洗：睡眠会话拼装（§5.2）、RR 伪迹过滤（§5.3）
  ▼
夜间特征 NightFeatures：HRV、夜间静息心率、呼吸率、温度、血氧、睡眠指标（§5.3–5.5、§5.9.1）
  │ ② 个人基线：稳健统计、冷启动收缩、异常夜剔除（§5.6）
  ▼
z-score + 数据质量（§5.7）
  │ ③ 评分合成：恢复（§5.8）、睡眠（§5.9）、负荷（§5.10）
  ▼
分数 + 贡献拆解 + 置信度
  │ ④ 计算时机：初步 → 最终 → 锁定；可重放、带版本（§5.13）
  ▼
SwiftData
```

设计原则：
1. **先清洗，后统计**：伪迹在源头处理掉，不指望后面的平均把它“抹平”。
2. **只和自己比**：所有判断都基于偏离个人基线的程度；人群数据只用作冷启动的先验。
3. **稳健优先**：用中位数、MAD、加权中位数和截断，防止单个异常值主导结果。
4. **缺失可见**：数据不足时降低置信度或者不出分，绝不悄悄瞎估。
5. **不用未来数据**：计算第 N 晚时，基线只使用第 N 晚**之前**的数据。
6. **可重放**：分数 = f(特征, 基线, 配置)，同样的输入永远得到同样的输出。

### 5.1 心率参数
- 最大心率 HRmax：初始值 = 208 − 0.7 × 年龄（Tanaka 公式）；之后如果观测到更高的心率（运动中 30 秒滑动均值），自动上调，也可以在设置里手动覆盖。
- 静息心率 RHR：取夜间静息心率（§5.4）的基线 μ（§5.6）。
- 心率储备比 HRR% = (HR − RHR) / (HRmax − RHR)，截断在 [0, 1]。
- 心率区间（按 HRR%）：Z1 50–60%、Z2 60–70%、Z3 70–80%、Z4 80–90%、Z5 90–100%。

### 5.2 睡眠会话拼装

> 睡眠时段是 HRV、夜间心率和所有夜间指标的取值窗口，必须最先算准。

**输入**：候选窗口内（前一天 12:00 到当天 18:00，当地时间）的全部 `sleepAnalysis` 样本。

**步骤**：
1. **来源优先级**：分期样本（核心、深睡、REM、清醒、未指定睡眠）只采用窗口内有数据的、优先级最高的那一个来源：Apple Watch > iPhone > 其他 App。`inBed`（在床）样本可以来自任何来源，取并集；它通常由 iPhone 的睡眠专注模式写入。
2. **同源重叠**：同一来源的样本在时间上重叠时，保留创建时间较晚的那条。
3. **碎片合并**：按时间排序后，相邻睡眠片段的间隔 ≤ 45 分钟时，合并成同一个会话，间隔计为清醒。间隔在 45–120 分钟之间、且两段都落在夜间窗口（19:00 到次日 11:00）内时，同样合并（分段睡眠），但这段长清醒要单独标记。
4. **会话分类**：
   - **主睡眠**：睡着时长 ≥ 3 小时、中点落在 19:00 到次日 15:00 之间的会话中，睡着时长最长的那一个。每个周期最多一个。
   - **小睡**：其余睡着时长 ≥ 15 分钟的会话；不足 15 分钟的忽略。
   - 夜班或作息颠倒时没有符合条件的会话，就取睡着时长最长、且 ≥ 3 小时的会话作为主睡眠。
5. **边界**：入睡时刻 = 第一个“睡着”分期的开始；醒来时刻 = 最后一个“睡着”分期的结束（之后的清醒不计入）。有 `inBed` 时，上床时刻 = 与会话重叠的 `inBed` 中最早的开始时间。
6. **佩戴检测**：主睡眠内连续 60 分钟以上没有任何心率点，标记为“部分未佩戴”；整晚没有分期数据，标记为“未佩戴”，不出恢复分数。
7. **时区**：全部用 UTC 存储，同时记录醒来时刻的时区偏移（优先读取样本元数据 `HKMetadataKeyTimeZone`）。判断“夜间窗口”时，使用当晚的当地时间。
8. **手动修正**（P1）：Apple 偶尔会把“躺着看书”识别成睡眠。睡眠页允许手动调整主睡眠的起止时间。修正值作为覆盖层单独保存，不改动 HealthKit 原始数据；重算时优先采用。

**分期的使用原则**：
- 统计时长时使用原始分期，不做任何修改。
- 统计事件时加阈值：只有持续 ≥ 2 分钟的清醒段才算一次“觉醒”，避免 30 秒级的分期跳变把觉醒次数虚报得很高。
- 绘制睡眠图（hypnogram）时，把不到 1 分钟的分期片段并入相邻的较长片段；这一步只影响显示。

### 5.3 RR 清洗与夜间 HRV

#### 5.3.1 读取
- 用 `HKHeartbeatSeriesQuery` 逐段读取每拍的 `timeSinceSeriesStart` 和 `precededByGap`。
- 第 i 拍的 RR_i = t_i − t_(i−1)，**只有当第 i 拍的 `precededByGap = false` 时才成立**。遇到间隙就断开，不跨间隙计算 RR 和相邻差值。

#### 5.3.2 伪迹过滤（三层）
| 层 | 规则 | 目的 |
|---|---|---|
| 生理范围 | RR 不在 [300, 2000] ms 内（即心率 30–200 之外）的剔除 | 去掉明显的误检 |
| 局部中位数 | 与前后各 5 拍（共 11 拍）的中位数相差超过 20% 的剔除 | 比“和上一拍比”更稳，因为上一拍本身可能就是伪迹 |
| 早搏模式 | 一短一长的成对 RR（短的 < 局部中位数 × 0.8，紧跟着长的 > 局部中位数 × 1.2），两拍都剔除 | 去掉期前收缩和随后的代偿间歇 |

- 被剔除的 RR **直接删除，不插值**。计算相邻差值时，只使用原本就相邻、且都有效的两个 RR。
- **整段验收**：有效 RR ≥ 40 个、剔除率 ≤ 20%、序列时长 ≥ 45 秒，三个条件同时满足，这一段才保留。

#### 5.3.3 每段特征
- 每段计算：RMSSD = √mean(ΔRR²)、ln RMSSD、段内平均心率、SDNN、有效拍数、剔除率。
- **上下文标注**：段中点所处的睡眠分期（来自 §5.2），以及它在夜间的位置（0 = 入睡，1 = 醒来）。
- **扰动检测**：段内平均心率高于当晚夜间静息心率（§5.4）的 1.15 倍时，判定为翻身或短暂醒来造成的扰动，整段丢弃。

#### 5.3.4 夜间合并
每段的权重：
```
w_i = 质量 q_i × 位置 p_i × 分期 s_i
q_i = min(1, 有效拍数 / 60) × (1 − 剔除率)
p_i = 0.7（前 1/3 夜）| 1.0（中 1/3）| 1.5（后 1/3）
s_i = 1.3（深睡）| 1.0（核心）| 0.8（REM）| 0（清醒，直接丢弃）
```
- 有效段 ≥ 3：当晚 ln RMSSD 取**加权中位数**。
- 有效段 = 2：取加权平均。
- 有效段 = 1：直接采用这一段，HRV 质量记为低。
- 同时记录段间离散度（加权四分位距 IQR），离散度过大时降低质量（§5.7）。
- 这样加权的原因：前半夜的 HRV 容易受晚餐、酒精、入睡前活动的影响；REM 期间交感神经波动大；后半夜深睡时的 HRV 最能代表身体恢复到了什么程度。

#### 5.3.5 三种 HRV 模式：分别建基线，不混在一起算
夜间被动测量是在睡着时，晨起主动测量是在清醒坐着时，两者的生理状态不同，数值有系统性差异。**混在一起算基线会让基线偏移**。所以三种来源各自维护独立的基线：

| 模式 | 来源 | 基线 | 质量上限 |
|---|---|---|---|
| 夜间 `night` | 主睡眠内的 heartbeat 序列 | 夜间 ln RMSSD 基线 | 高 |
| 晨测 `morning` | 醒来后 60 分钟内，手表“正念 · 呼吸”产生的序列 | 晨测 ln RMSSD 基线 | 高 |
| 兜底 `sdnn` | 主睡眠内 Apple 的 SDNN 样本（只在没有任何 heartbeat 序列时使用） | ln SDNN 基线 | 低 |

恢复分数用到的 HRV z-score：
```
夜间和晨测都有：z_hrv = (Q_n · z_night + 1.5 · Q_m · z_morning) / (Q_n + 1.5 · Q_m)
只有其中一个：直接用那一个
两个都没有：用 z_sdnn，HRV 质量记为低
```
- Q_n、Q_m 是夜间和晨测各自的 HRV 质量分（§5.7）。晨测累计不到 7 次时，晨测基线还不可靠，只展示数值，不参与合成。
- **展示值**：界面上的“HRV”始终显示 RMSSD（毫秒）。兜底模式下，用历史上同时有 RMSSD 和 SDNN 的夜晚（≥ 20 晚）拟合个人回归 `ln RMSSD ≈ a + b · ln SDNN`，显示估算值并标注“估算”。z-score 仍然基于 SDNN 自己的基线计算，不经过这个回归，避免叠加回归误差。

### 5.4 夜间静息心率
- **样本池**：主睡眠内的心率点（去掉持续 ≥ 5 分钟的清醒段里的点），**再加上**每段有效 heartbeat 序列的平均心率。后者能明显提高夜间的采样密度。
- **主指标**：样本池的**第 10 百分位**（至少需要 10 个样本）。夜间心率点只有每几分钟一个，“5 分钟滑动均值的最低值”实际上会退化成单个点的最小值，容易被一次偏低的读数带偏；用百分位更稳。
- **辅助指标**：
  - 夜间平均心率。
  - **最低心率出现时刻**：取 15 分钟滑动中位数的最低点，记录它在夜间的位置（0–1）。最低点出现在后 1/3 夜，通常说明身体前半夜在“加班”（酒精、晚餐过晚、晚间高强度训练、压力）。这一项作为日志洞察的输入。
- **兜底**：样本不足 10 个时，退回使用 Apple 的 `restingHeartRate`，质量记为中。

### 5.5 其他夜间生命体征
| 指标 | 夜间取值 | 最少样本 | 衍生量 |
|---|---|---|---|
| 呼吸率 | 主睡眠内样本的中位数 | 3 | z_resp |
| 手腕温度 | 当晚的单个值 | 1 | Δt = 当晚值 − 基线中位数（°C） |
| 血氧 | 主睡眠内样本的中位数 | 3 | 低于 90% 的样本占比 |
| 呼吸紊乱 | 当晚的单个值 | 1 | 是否处于 Apple 定义的“升高”区间（取值方式在 M0 实测确认） |

### 5.6 个人基线
**适用指标**：夜间 ln RMSSD、晨测 ln RMSSD、ln SDNN、夜间静息心率、呼吸率、手腕温度、血氧、睡着时长、修复性睡眠时长、入睡耗时。

**计算方法**：
1. **窗口**：第 N 晚之前最近的 30 个**有效夜晚**，不含第 N 晚本身。
2. **稳健统计**：μ = 中位数；σ = 1.4826 × MAD。
3. **σ 下限**：防止某项指标近期特别稳定时，一点小波动就算出很大的 z-score。

| 指标 | σ 下限 |
|---|---|
| ln RMSSD / ln SDNN | 0.06 |
| 夜间静息心率 | 1.5 bpm |
| 呼吸率 | 0.3 次/分 |
| 手腕温度 | 0.15 °C |
| 血氧 | 0.5 % |

4. **冷启动收缩**：有效夜数 n 不足 30 时，把个人统计值向人群先验（按年龄、性别查表）收缩：
```
μ = (n₀ · μ_先验 + n · μ_个人) / (n₀ + n)，n₀ = 7；σ 用同样的方式计算
```
导入历史数据后通常一开始就有 30 晚，这一步主要用于换新手表，或者很久没戴表之后。有效夜数少于 4 晚时，显示“基线建立中”。

5. **哪些夜晚算“有效”**：数据质量至少为中（§5.7），而且没有被标记为排除。
   - 自动排除：经过确认的生病夜晚（§5.12.1）；跨越 3 个及以上时区后的头 2 晚。
   - 手动排除：在设置里指定日期。
   - **不排除**饮酒、熬夜这类行为夜。它们是真实生活的一部分，排除掉会让基线虚高，以后每天都显得“恢复不好”。

**双时间尺度趋势**（用于趋势卡片和周报，不影响当天的分数）：
- 7 天均值对比 60 天正常范围。正常范围 = 60 天中位数 ± 0.5σ，即“最小有意义变化”：
  - 7 天 HRV 均值在范围内：正常
  - 高于上沿：适应良好
  - 低于下沿：疲劳累积
- **7 天 ln RMSSD 变异系数（CV）**：CV 超过个人 60 天中位数的 1.5 倍、同时均值在下降时，提示“适应不良”，意思是训练或生活压力超出了身体的承受能力。即使单日分数看起来还可以，也要提示。

### 5.7 数据质量
每晚计算一个 0–1 的质量分，再映射为高 / 中 / 低。

| 分量 | 计算方式 | 权重 |
|---|---|---|
| Q_hrv | 按有效段数：≥ 3 段 → 1.0，2 段 → 0.7，1 段 → 0.4；SDNN 兜底 → 0.3；没有 HRV → 0。段间离散度 > 0.4（ln 单位）时再乘以 0.8。有晨测时直接取 1.0 | 0.5 |
| Q_hr | 睡眠期间每小时心率点数 ÷ 6，最高为 1 | 0.2 |
| Q_sleep | 有分期数据时为 1，再乘以佩戴覆盖率（没有心率空窗的时长占比） | 0.2 |
| Q_vitals | 呼吸率、温度、血氧三项中可用的项数 ÷ 3 | 0.1 |

- 总质量 Q = 各分量的加权和；**高：≥ 0.75；中：0.5–0.75；低：< 0.5**。
- 质量低时照常出分，但分数环改用灰色描边，并附上原因，例如“昨晚只有 1 段有效 HRV”。
- Q_hrv = 0（没有任何 HRV 数据）时，不出恢复分数。

### 5.8 恢复分数 Recovery（0–100%）

#### 5.8.1 输入（z-score 一律截断到 [−3, 3]）
| 分量 | 定义 | 权重 |
|---|---|---|
| z_hrv | 见 §5.3.5 | 0.55 |
| z_rhr | −(夜间静息心率 − μ) / σ（心率越低越好） | 0.25 |
| z_sleep | (睡眠分 − 80) / 12（睡眠分见 §5.9.4） | 0.20 |

睡眠分本身已经是相对于个人睡眠需求计算的，所以这里用固定映射，不再套一层个人基线。

#### 5.8.2 连续扣分项
用连续函数代替阶梯式扣分，避免分数在阈值两侧突然跳变：
```
pen_resp = min(0.6, 0.3 · max(0, z_resp − 1.0))
pen_temp = min(1.2, 0.8 · max(0, Δt − 0.3) / 0.5)
pen_spo2 = min(0.4, 0.1 · max(0, 95 − 夜间血氧中位数))
pen_bd   = 0.2（呼吸紊乱处于“升高”区间时，否则为 0）
扣分 = 以上四项之和
```

#### 5.8.3 合成
```
raw = 0.55·z_hrv + 0.25·z_rhr + 0.20·z_sleep − 扣分
Recovery = 100 / (1 + e^−(1.4·raw + 0.35))
```
- raw = 0（各项都正好在基线上）时，Recovery 约为 59%，位于黄区上沿。
- 分区：**绿 ≥ 67**、**黄 34–66**、**红 ≤ 33**。
- **缺失时重新分配权重**：z_rhr 或 z_sleep 缺失时，把剩下各项的权重按比例放大，使总和仍为 1。如果连 z_hrv 都没有（SDNN 也没有），不出分。
- **矛盾信号**：z_hrv > 2 且 z_rhr < −1，即 HRV 异常偏高、但静息心率也偏高时，z_hrv 的值按 1 封顶，并标记“信号矛盾”。这种组合可能是副交感神经饱和，也可能是生病早期，不应该显示成漂亮的绿色。
- **门控上限**：生病预警（§5.12.1）进入“可能不适”级别时，Recovery 最高为 33。
- 分数本身**不做跨天平滑**。恢复分数就是要反映当天的状态；平滑放在 7 天趋势里做（§5.6）。

#### 5.8.4 贡献拆解（瀑布图）
sigmoid 是非线性的。简单按比例分配贡献，在 raw 接近 0、各项正负相互抵消时会严重失真。所以采用**精确 Shapley 值**：
- 参与者：z_hrv、z_rhr、z_sleep，以及各扣分项。最多 7 个，2⁷ = 128 次求值，计算开销可以忽略。
- 某一项“不参与”时，令它取基线值：z = 0，扣分 = 0。
- 各项贡献之和恰好等于 Recovery − 59。瀑布图从“基线 59%”出发，逐项加减，最后落到当天的分数。

#### 5.8.5 个人化校准（自用专属）
- 累计 45 天以上的“主观精力 1–5 分”后，可以在实验室页运行权重拟合：以主观精力为因变量，各 z-score 和扣分项为自变量，做**岭回归**，并以默认权重作为收缩目标，防止过拟合。
- 按时间切分验证：用前 70% 的天数拟合，后 30% 评估。新权重在验证集上的 Spearman 相关系数比旧权重高出至少 0.05，才建议采用。
- 采用后生成一个新的 configVersion，并对全部历史重算；随时可以回滚。

### 5.9 睡眠指标与睡眠需求

#### 5.9.1 基础指标
| 指标 | 定义 |
|---|---|
| 睡着时长 TST | 主睡眠内核心 + 深睡 + REM + 未指定睡眠的总时长 |
| 入睡耗时 | 入睡时刻 − 上床时刻（只在有 `inBed` 时计算） |
| 夜间清醒 WASO | 入睡到醒来之间的清醒总时长 |
| 觉醒次数 | 持续 ≥ 2 分钟的清醒段的个数 |
| 睡眠效率 | TST ÷ (醒来时刻 − 上床时刻)；没有 `inBed` 时改用 TST ÷ (醒来时刻 − 入睡时刻)，并标注为“睡眠期效率” |
| REM 潜伏期 | 入睡到第一段 REM 的时长 |
| 修复性睡眠 | 深睡 + REM 的时长，以及它占 TST 的比例 |

深睡和 REM 都和**个人基线**比较，不和人群标准比较。个体差异本来就大，而且 Apple 的分期本身也有误差。

#### 5.9.2 睡眠一致性
入睡和起床时间会跨越午夜，**不能直接算均值和标准差**：23:50 和 00:10 的算术平均是 12:00。
- **主指标：睡眠规律指数 SRI**（Phillips 等，2017）：
  - 把最近 7 天切成 1 分钟一片，每片标记为“睡着 / 醒着 / 未知”（小睡也算睡着）。
  - SRI = −100 + 200 × P(时刻 t 与 t + 24 h 状态相同)。只统计两端状态都已知的时间片对。
  - 对外显示为 0–100，即 max(0, SRI)。一般人在 60–85 之间。
  - 至少需要 5 天有效数据，不够时显示“数据不足”。
- **辅助指标：环形统计**，用于“就寝时间波动 ±xx 分钟”这类文案：
```
θ = 2π × 一天中的分钟数 / 1440
R = |mean(e^(iθ))|
环形均值 = arg(mean(e^(iθ)))，再换算回时刻
环形标准差（分钟）= √(−2 ln R) × 1440 / (2π)
```
- **作息类型**（P2）：取自由日（周末，或用户标记的不定闹钟的日子）的睡眠中点，按睡眠负债校正后得到 MSFsc；它和工作日睡眠中点的差值就是“社交时差”。

#### 5.9.3 睡眠需求
```
N0_t   = 基础需求 + 负荷追加_t − 小睡抵扣_t             （当晚“本来就该睡”的量，不含还债）
D_t    = clamp(λ · D_(t−1) + (N0_t − TST_t), 0, 10 h)    （睡眠负债，逐晚递推）
需求_t = N0_t + min(2 h, ρ · D_(t−1))                     （今晚建议的睡眠量）
λ = 0.8（半衰期约 3 晚），ρ = 0.3
```
- **负荷追加**：4 分钟 × max(0, 昨日负荷 − 8)，最多 52 分钟。
- **小睡抵扣**：本周期内小睡的睡着时长 × 0.8，因为小睡缺少完整的睡眠周期。
- **负债为什么用递推，而不是简单累加**：睡多了可以偿还负债（N0 − TST 为负数时）；负债会随时间自然衰减，不会越滚越大；最低为 0，最高 10 小时。
- 计算负债时用 N0（不含还债部分）作为参照，避免“需求里包含负债，负债又由需求算出来”的循环依赖。
- **基础需求的个性化**（积累 60 晚以后开始，每月更新一次）：
  - 方法 A：连续 2 晚以上负债都 < 30 分钟之后的自由日夜晚，取它们 TST 的中位数，作为“自然睡眠长度”。
  - 方法 B：用分段线性（折线）回归拟合“TST → 次日 z_hrv”，取收益开始变平的那个拐点。
  - 候选值 = A、B 的平均值，限制在 6.5–9.5 小时之间；平滑更新：基础需求 = 0.7 × 旧值 + 0.3 × 候选值。如果 A、B 相差超过 1 小时，本月不更新，并在实验室页给出提示。
- 需求的各个组成部分（基础、负荷追加、负债偿还、小睡抵扣）都保存下来，供睡眠页画堆叠条形图。

#### 5.9.4 睡眠分（0–100，摘要页的睡眠环显示这个值）
```
睡眠分   = 100 × (0.55·时长达成 + 0.15·效率分 + 0.15·一致性分 + 0.15·修复分)
时长达成 = min(1, (TST + 小睡抵扣) / 需求)
效率分   = clip((睡眠效率 − 0.75) / 0.20, 0, 1)
一致性分 = SRI 显示值 / 100
修复分   = clip(0.5 + 0.25 · z_修复性睡眠时长, 0, 1)
```
- “时长达成”单独展示为“睡眠表现 %”，口径和 WHOOP 一致。
- 和分期有关的分量只占 0.15。Apple 的分期与医院多导睡眠图相比有一定误差，不宜给太高的权重。

#### 5.9.5 作息建议
- 建议入睡时间 = 目标起床时间 − 今晚的睡眠需求 − 个人入睡耗时的中位数（没有 `inBed` 数据时默认 15 分钟）。
- **渐进调整**：如果算出来的时间比最近 7 天的平均入睡时间（环形均值）早 60 分钟以上，每晚最多提前 30 分钟，逐步靠拢，避免给出不现实的建议。
- 同时给出三档：要睡够 100% / 85% / 70% 的需求，分别要几点入睡。

### 5.10 负荷分数 Strain（0–21）
1. 构建周期内的**分钟级心率时间线**：
   - 运动时段用原始高频心率，按分钟取平均。
   - 非运动时段：间隔 ≤ 15 分钟的点线性插值；更长的空窗按 §2.2 处理。
   - 未佩戴时段不计入。
2. 每分钟负荷（Banister TRIMP）：
   - 只计 HRR% ≥ 0.25 的分钟，排除日常久坐和慢走的噪声。
   - 男性：x · 0.64 · e^(1.92x)；女性：x · 0.86 · e^(1.67x)，其中 x 为 HRR%。
3. 周期 TRIMP = 各分钟负荷之和。
4. 对数映射：
```
Strain = min(21, 5.3 · ln(1 + TRIMP / 10))
```
校准锚点：TRIMP 20 ≈ 5.8（轻松日）、87 ≈ 12（中等训练）、300 ≈ 18（高强度）、≥ 600 ≈ 21（封顶）。
5. 每次训练单独计算一个训练负荷（只算该训练时段），用于训练详情页。

### 5.11 负荷目标与负荷平衡
- **今日目标区间**由恢复分数决定（初始值）：
  - 绿：14–18；黄：10–14；红：0–10
  - 再根据负荷平衡微调：ACWR > 1.3 时，区间下调 2。
- **负荷平衡 ACWR** = 最近 7 天平均 TRIMP / 最近 28 天平均 TRIMP。
  - < 0.8 欠训练，0.8–1.3 适宜，> 1.5 受伤风险升高。

### 5.12 生病预警与其他派生指标

#### 5.12.1 生病预警（M2）
四个信号，都相对个人基线判断：
- T：Δt ≥ +0.5 °C
- R：z_resp ≥ 1.5
- H：z_hrv ≤ −1.5
- C：夜间静息心率 ≥ μ + 2σ

判定：
- **注意**：T 成立，且 R、H、C 中至少一个成立，持续 1 晚；或者 T 不成立，但 R、H、C 三个同时成立。
- **可能不适**：上述条件连续 2 晚成立。此时推送提醒，在日志中预填“不适”，并给 Recovery 加上 33 的上限（§5.8.3）。
- **混杂因素**：当晚的日志记录了饮酒或桑拿时，只做提示，不推送，也不自动排除基线。酒精同样会让体温和心率升高、HRV 降低。
- 用户在日志中确认“不适”，或者连续 2 晚触发“可能不适”时，这些夜晚自动从基线中排除，直到信号消失后的第一晚为止。

#### 5.12.2 其他派生指标
| 指标 | 规则 | 里程碑 |
|---|---|---|
| 压力（0–3） | 非运动、步数低的 15 分钟窗口内，心率相对夜间静息基线的升高幅度，结合最近的 HRV z-score。数据稀疏时显示“数据不足”。 | M3 |
| 身体年龄 | 用最大摄氧量、静息心率、HRV、睡眠一致性、日均步数、每周 Z2+ 时长，按公开文献系数映射为年龄偏移，每周更新一次。 | M4 |
| 心肺适能趋势 | 最大摄氧量 + 1 分钟心率恢复 + 同配速下心率的变化 | M4 |

### 5.13 计算时机、重算与版本

**每个周期的分数状态**：
```
等待数据 ──主睡眠结束且有 HRV──▶ 初步 ──数据到齐，或醒来满 3 小时──▶ 最终 ──满 48 小时──▶ 锁定
```
- **“主睡眠结束”的判定**：最后一个“睡着”分期结束后，20 分钟内没有新的睡眠样本写入。
- **初步**：可以出分了。数据质量至少为中时，立即推送“恢复分数已生成”；质量为低时，等到“最终”再推送。
- **最终**：手腕温度、呼吸率等较晚写入的数据到齐后（或者醒来满 3 小时后），再算一次。如果分数变化 ≥ 5，在卡片上标注“已更新”。
- **锁定**：48 小时后不再自动重算，除非算法配置变了，或者用户手动触发。
- **幂等**：重算一个周期，就是用同样的特征、截至前一晚的基线和当前配置重新求值。HealthKit 增量查询返回的新增或删除落在某个周期的窗口内时，只把这个周期标记为待重算。
- **基线级联**：第 N 晚的特征变了，会影响之后 30 晚的基线。所以按时间顺序向后增量重算；这一步只重算基线和分数，不需要重新读取 HealthKit。
- **版本**：每条分数记录都保存 `algorithmVersion`（代码版本）、`configVersion`（参数版本）和输入特征的哈希值。哈希值没变就跳过重算。

### 5.14 校准与验证

**工具链**：
- **回放命令行工具 `vigor-replay`**：在 Mac 上运行，和 App 共用 `VigorScoring` 包。输入实验室页导出的调试快照 JSON，输出逐晚的特征和分数 CSV。
- **黄金快照测试**：把一份固定的个人数据快照及其输出结果纳入单元测试。每次改算法后自动比对，生成一份“哪些天的分数变了、变了多少”的报告，确保每一处变化都是有意为之。
- **探索分析**：前期可以用 Python + notebook 读取同一份 CSV，画图试公式；公式确定之后再移植到 Swift，并用命令行工具确认两边的结果一致。
- **消融对比**：在实验室页一键查看去掉任意一个分量后的分数分布，判断这个分量是不是真的有用。

**对照基准**：
| 基准 | 用来检验什么 | 目标 |
|---|---|---|
| 主观精力 1–5 分 | 恢复分数是否反映真实感受 | Spearman 相关系数 ≥ 0.3 |
| 分区分布 | 分数整体是否合理 | 绿 / 黄 / 红大致为 40% / 40% / 20% |
| 日间稳定性 | 分数是否跳得太厉害 | 相邻两天差值的中位数 ≤ 15 |
| Apple Vitals 异常提示 | 生病预警会不会漏报 | Apple 提示异常的夜晚，我们也应该至少给出“注意” |
| **Polar H10 胸带**（可选，约 ¥600） | RR 清洗和 RMSSD 是否准确 | 见下文 |

**Polar H10 验证方案**（胸带测的是心电，它的 RR 是金标准）：
- **晨测对比**：起床后同时佩戴手表和胸带，手表做 1 分钟“正念 · 呼吸”，胸带同步记录 RR（通过 Elite HRV 等 App 导出），连续 2 周。
- **夜间对比**（可选）：戴着胸带睡 2–3 晚，把每段手表序列和胸带同一时段的 RMSSD 逐段对比。
- **指标**：ln RMSSD 的 Bland–Altman 偏差与一致性界限，以及组内相关系数 ICC。目标：晨测 ICC ≥ 0.9，夜间单段 ICC ≥ 0.8。
- 根据验证结果，调整 §5.3.2 的伪迹阈值和 §5.3.4 的段权重。
- **延伸（P2）**：App 直接通过蓝牙标准心率服务读取 H10 的 RR，作为“专业晨测”模式，归入晨测基线，质量最高。

## 6. 功能需求

> 优先级：P0 = 核心闭环；P1 = 完整体验；P2 = 锦上添花。里程碑映射见 §10。

### 6.1 摘要页（P0）
- 大标题“摘要”，副标题为当前周期日期，以及数据最后同步时间。
- **主卡片**：三个环形仪表并排——恢复（红/黄/绿动态色）、负荷（带目标区间刻度）、睡眠分（§5.9.4）。点击各自进入详情。分数处于“初步”状态时，环下方显示小字“初步”（§5.13）。
- **教练一句话**：根据当日状态生成，例如“HRV 高于基线，适合安排高强度训练，目标负荷 14–18”。
- **固定指标**（可编辑、可排序）：HRV、夜间静息心率、呼吸率、手腕温度偏差、血氧。每张卡片 = 类别图标与名称 + 时间 + 大号数值 + 迷你趋势图 + 相对基线的箭头。
- **今日活动**：今天的训练列表、实时累积负荷。
- **亮点 Highlights**：自动生成 1–3 条趋势洞察，例如“本周平均 HRV 比上月高 8%”。
- 状态卡：未佩戴、校准中、数据质量低、生病预警。

### 6.2 恢复详情（P0）
- 大号分数 + 分区色 + 数据质量标识 + 分数状态（初步 / 最终）。
- **贡献拆解**：瀑布图，从“基线 59%”出发，展示 HRV、静息心率、睡眠、各扣分项各自让分数上升或下降了多少分（Shapley 值，各项之和精确等于总分，§5.8.4）。这是本产品最核心的差异点。
- 特殊状态提示：“信号矛盾”、“生病预警封顶”、“HRV 来自 SDNN 估算”（§5.8.3、§5.3.5）。
- HRV 来源说明：今天用了几段夜间序列、是否有晨测、各自的 z-score。
- 各输入指标的今日值 vs 基线范围（带状图）。
- **7 天趋势状态**：适应良好 / 正常 / 疲劳累积 / 适应不良（§5.6）。
- 最近 30 天恢复分数柱状图（按分区着色）。

### 6.3 睡眠页（P0）
- 昨夜睡眠图（hypnogram，按分期着色），叠加心率曲线。
- 睡眠需求 vs 实际：堆叠条形图，展示需求的构成（基础 / 负荷追加 / 负债偿还 / 小睡抵扣）。
- 睡眠分及四个分项（时长达成、效率、一致性、修复）；睡眠表现 %、入睡耗时、WASO、觉醒次数、REM 潜伏期。
- 一致性：SRI 分数 + “就寝时间波动 ±xx 分钟”+ 最近 7 天入睡 / 起床时间的点阵图。
- 夜间心率：最低心率出现时刻，后 1/3 夜才出现时给出提示（§5.4）。
- 睡眠负债趋势（14 天）。
- 今晚的作息建议：100% / 85% / 70% 三档入睡时间 + 一键设置提醒（§5.9.5）。
- 夜间生命体征：呼吸率、温度、血氧、呼吸紊乱。
- 手动修正睡眠时段（P1，§5.2）。

### 6.4 负荷页（P0：基础；P1：负荷平衡和空窗估算）
- 今日负荷仪表 + 目标区间。
- 全天心率时间线（分钟级），用区间色带标出，训练时段高亮。
- 心率区间分布（今日 / 本周）。
- 训练列表 → 训练详情：训练负荷、时长、能量、心率曲线、区间分布、1 分钟心率恢复。
- 负荷平衡 ACWR 趋势图（P1）。

### 6.5 日志 Journal（P1）
- 每天醒来后推送一份问卷，询问“昨天”的行为。默认题目：饮酒、睡前 3 小时进食、14 点后摄入咖啡因、睡前看屏幕、晚间训练、压力大、不适、旅行、桑拿、补剂。题目可自定义，题型支持“是/否”和“数量”。
- 自动填充项（来自 HealthKit）：咖啡因、酒精、正念时长、日照时间、情绪状态。
- 主观评分：精力 1–5 分（同时用作算法验证）。
- **影响洞察**：对每个行为，比较“做了”和“没做”时次日的恢复分数、HRV、睡眠表现，给出差值和置信度（Welch t 检验；两组各至少 5 个样本才显示）。

### 6.6 浏览 & 指标详情（P0）
- 浏览页：按类别分组列出全部指标，每个类别使用独立的类别色和图标。
- **指标详情页（通用模板）**：
  - 顶部分段控件：日 / 周 / 月 / 6 个月 / 年。
  - 图表：柱状图或折线图，叠加基线范围带；拖动查看具体数值。
  - 摘要行：区间内的平均值、范围。
  - “关于”说明：这个指标是什么，我们是怎么算的。
  - 数据来源和质量说明。

### 6.7 报告（P1）
- 周报（每周日晚上推送）、月报：三大分数的平均值和趋势、最好与最差的一天、训练汇总、睡眠负债变化、日志洞察排行。
- 文字总结由 AI 教练生成（§6.10）。

### 6.8 Apple Watch App（P1）
- 主界面：今日三个分数 + 当前累积负荷。
- **训练模式**：开启 `HKWorkoutSession`，实时显示心率、区间、本次训练负荷和全天累积负荷；结束后保存为 HealthKit 训练记录。
- 表盘复杂功能 / Smart Stack 小组件：恢复环、负荷仪表、建议入睡时间。
- 数据由 iPhone 计算，通过 WatchConnectivity 推送到手表；训练模式下由手表本地实时计算负荷。

### 6.9 小组件、通知、快捷指令（P1）
- iOS 主屏和锁屏小组件：三个分数（小 / 中尺寸）、建议入睡时间。
- 通知：
  - 恢复分数已生成（醒来并同步后）
  - 作息提醒（建议入睡时间前 30 分钟）
  - 晨测提醒（可选）
  - 生病预警
  - 周报
- App Intents：Siri 或快捷指令中问“今天恢复怎么样”、“今天负荷多少”。

### 6.10 AI 教练（P2）
- 优先使用端侧的 Apple Foundation Models 框架：免费、离线、数据不出设备。
- 端侧模型不可用时（设备不支持 Apple Intelligence，或所在区域未开放），退回使用 Claude API（用户在设置里填入自己的 key），只发送**脱敏后的每日汇总 JSON**，不发送原始数据。
- 能力：每日教练一句话的润色、周报和月报总结、对话式提问（例如“为什么我这周恢复都不好？”），结合日志洞察回答。

### 6.11 实验室（P0，自用必备）
- 任选一个夜晚或周期，查看原始数据：心率点、heartbeat 序列（RR 散点图 / Poincaré 图，伪迹用不同颜色标出）、睡眠分期、会话拼装过程（来源、合并的碎片）。
- **HRV 段表**：每段的时间、分期、夜间位置、有效拍数、剔除率、RMSSD、权重 q/p/s、是否采用及丢弃原因。
- 中间变量：基线 μ/σ（含历史曲线和冷启动收缩前后对比）、各 z-score、扣分项、Shapley 贡献、TRIMP、睡眠负债递推过程。
- 数据质量明细（各分量得分）。
- 参数面板 + 全量重算 + 新旧版本对比；消融对比；权重拟合与基础睡眠需求个性化的建议值（§5.8.5、§5.9.3）。
- 导出：CSV / JSON（每日汇总、原始特征）；调试快照（供 `vigor-replay` 和黄金快照测试使用，§5.14）。

### 6.12 设置（P0）
- 个人资料：生日、性别、身高、体重（默认读取 HealthKit）。
- 最大心率、基础睡眠需求：手动覆盖。
- 目标起床时间（或跟随睡眠计划）。
- 通知开关。
- 固定指标的编辑与排序。
- 基线管理：排除指定夜晚。
- 数据：重新导入历史、备份与恢复、清空数据。
- 单位：°C / °F。

## 7. 视觉与交互设计

### 7.1 设计原则
- **Apple Health 的设计语言**：浅色和深色模式下都使用系统分组背景（`systemGroupedBackground`），配合卡片（`secondarySystemGroupedBackground`），用类别色标识领域，数字永远是视觉主角。
- **解释优先**：任何分数旁边都有入口，可以一键看到“为什么”。
- **克制**：一张卡片只讲一件事；动效只用于状态变化（分数环增长、切换图表区间）。

### 7.2 设计令牌
| 令牌 | 值 |
|---|---|
| 恢复色 | 绿 `systemGreen` / 黄 `systemYellow` / 红 `systemRed` |
| 负荷色 | `systemBlue`（与活动橙区分） |
| 睡眠色 | `systemIndigo`；分期：清醒 橙、REM 浅蓝、核心 蓝、深睡 靛 |
| 心脏类 | `systemPink` |
| 呼吸类 | `systemCyan` |
| 体温类 | `systemPurple` |
| 活动 / 训练 | `systemOrange` |
| 大数字 | SF Pro Rounded，Bold，34–56 pt |
| 卡片标题 | SF Pro，Semibold，15 pt，类别色 + SF Symbol |
| 卡片圆角 | 与系统一致的同心圆角（约 20 pt） |
| 间距 | 卡片内边距 16，卡片间距 12，页面左右边距 16 |

- 全面支持动态字体（Dynamic Type）和 VoiceOver；颜色之外还要有文字或形状区分分区（色弱友好）。
- 导航栏和标签栏使用 iOS 26 系统的液态玻璃材质，不自定义。

### 7.3 关键组件
- `ScoreRing`：环形仪表，支持分区色、目标区间刻度、数值动画。
- `MetricCard`：Apple Health 式的指标卡片（类别头 + 数值 + 迷你图 + 基线箭头）。
- `RangeChart`：带基线范围带、支持拖动选中的通用趋势图。
- `ContributionWaterfall`：恢复分数的贡献瀑布图。
- `Hypnogram`：睡眠分期图 + 心率叠加。
- `HRTimeline`：分钟级心率时间线 + 区间色带。
- `QualityBadge`：数据质量标识。

## 8. 技术架构

### 8.1 工程结构
```
Vigor.xcodeproj
├── Vigor (iOS App)
├── VigorWatch (watchOS App)
├── VigorWidgets (iOS 小组件 + 手表复杂功能)
└── Packages/
    ├── VigorScoring      纯算法：基线、RMSSD、恢复、负荷、睡眠、洞察（零依赖，100% 单元测试）
    ├── VigorHealth       HealthKit 封装：权限、查询、观察者、heartbeat 读取；提供 HealthStore 协议 + 回放实现
    ├── VigorStore        SwiftData 模型与仓储
    ├── VigorDesign       设计令牌与通用组件
    └── VigorCoach        AI 教练（Foundation Models / Claude API 适配）
```

### 8.2 数据流
```
HealthKit ──(HKObserverQuery + 后台推送)──▶ SyncEngine
                                              │ HKAnchoredObjectQuery 增量拉取
                                              ▼
                                       特征提取 FeatureExtractor
                                       （夜间特征、分钟心率、训练）
                                              │
                                              ▼
                                  VigorScoring（纯函数，带 configVersion）
                                              │
                                              ▼
                                SwiftData（App Group 共享容器）
                                   │            │              │
                                   ▼            ▼              ▼
                                 iOS UI      小组件      WatchConnectivity → 手表
```
- **原始数据不复制**：HealthKit 是唯一的事实来源；本地只存派生特征和分数。
- **可重放**：分数 = f(特征, 配置)。改了算法只需对特征重新计算，速度快且结果可复现。
- 后台任务：
  - 订阅睡眠、HRV、心率、训练、温度的后台推送（`enableBackgroundDelivery`），醒来后自动出分。
  - `BGProcessingTask`：每天凌晨做基线更新、日志相关性分析和洞察生成。
- 首次导入：分批（每次 7 天）拉取历史数据，显示进度；heartbeat 序列读取开销大，单独排队执行。

### 8.3 数据模型（SwiftData）
| 模型 | 关键字段 |
|---|---|
| `SleepSession` | 开始/结束、上床时刻、时区偏移、是否主睡眠、来源、合并碎片数、各分期时长、效率、入睡耗时、WASO、觉醒次数、REM 潜伏期、佩戴状态、手动修正覆盖层 |
| `NightFeatures` | 关联睡眠；夜间 / 晨测 / SDNN 三种 HRV 值及 HRV 模式、有效段数与总段数、段间离散度、`[HRVWindow]`（每段的时间、分期、位置、拍数、剔除率、RMSSD、权重、是否采用）、夜间静息心率 P10、夜间平均心率、最低心率时刻、呼吸率、温度及偏差、血氧中位数及 < 90% 占比、呼吸紊乱、质量分及各分量、是否排除出基线及原因 |
| `Cycle` | 开始/结束、分数状态（等待 / 初步 / 最终 / 锁定）、恢复分数及 Shapley 贡献、矛盾 / 封顶标记、负荷、TRIMP、负荷目标、睡眠需求及构成、睡眠负债 D、睡眠分及四个分项、睡眠表现、SRI、生病预警级别、algorithmVersion、configVersion、输入哈希 |
| `MinuteHR` | 按周期分块压缩存储的分钟心率数组（用于时间线和重算） |

| `Baseline` | 指标、日期、μ、σ、样本数 |
| `JournalEntry` | 周期、行为项（键值）、主观精力 |
| `Insight` | 类型、内容、生成时间、关联指标 |
| `ScoringConfigRecord` | 版本号、参数 JSON、是否当前版本 |

### 8.4 开发与测试策略
- **模拟器没有真实健康数据**：在 `VigorHealth` 中提供 `HealthStore` 协议，以及两个实现——真机实现和 **回放实现**。回放实现读取从真机导出的 JSON 快照（实验室页提供“导出调试快照”）。UI 开发全部在模拟器上用回放数据完成。
- `VigorScoring` 单元测试覆盖：
  - RR 清洗：生理范围、局部中位数、早搏成对剔除、`precededByGap` 断开、整段验收门槛。
  - HRV 合并：加权中位数、1 / 2 / ≥ 3 段的分支、三种模式的基线隔离与合成。
  - 基线：σ 下限、冷启动收缩、异常夜剔除、不使用未来数据。
  - 恢复：锚点数值（raw = 0 → 59%）、缺失时权重重新分配、矛盾信号、生病封顶、Shapley 之和等于总分减 59。
  - 睡眠：会话拼装（多来源、碎片合并、分段睡眠、小睡、夜班）、跨零点的环形统计、SRI、负债递推的边界（0 和 10 h）。
  - 周期切分边界（小睡、跨零点、跨时区、未佩戴）；负荷各锚点数值。
- `vigor-replay` 命令行工具 + 黄金快照测试：每次算法改动都输出分数差异报告（§5.14）。
- 预览数据：每个界面都配多种 SwiftUI Preview 状态（绿/黄/红、校准中、无数据、低质量）。

### 8.5 分发（企业证书）
- 在企业开发者账号中为 App ID 开启 **HealthKit**（包括 Background Delivery）、App Groups；手表 App 和小组件使用相同的 App Group。
- 安装方式：通过 Xcode 直接安装，或用 HTTPS 托管 manifest.plist 进行 OTA 安装；首次安装后需要在“设置 → 通用 → VPN 与设备管理”中信任企业开发者。
- 描述文件每年到期：到期前 30 天在 App 内提醒。用相同的 Bundle ID 覆盖安装后数据会保留。
- 如果证书被吊销，App 将无法启动 → 依赖 §9.4 的备份兜底。

## 9. 非功能需求

### 9.1 性能
- 冷启动到摘要页显示 < 1 秒（全部读缓存）。
- 增量同步 + 重算单个周期 < 2 秒。
- 首次导入 180 天历史 < 3 分钟（在前台进行，显示进度）。

### 9.2 功耗
- iPhone：只依赖后台推送和每日一次的处理任务，不做轮询。
- 手表：只有训练模式会开启传感器会话；不做全天候的高频采集。

### 9.3 隐私
- 所有数据只保存在本机，不接入任何统计 SDK。
- AI 教练使用云端模型时，需要单独开启，并在每次发送前可以预览发送内容。

### 9.4 备份

## 11. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 夜间 heartbeat 段太少 | 恢复分数噪声大 | M0 先量化；不够就推广晨测；质量标识对用户可见 |
| 日常心率稀疏 | 负荷被低估 | 训练模式 + 空窗估算；在 UI 上说明“非训练时段为估算值” |
| 没有金标准可以对照 | 分数是否“准”无从判断 | 用主观精力和 Apple Vitals 做相关性验证；可选 Polar H10 验证 RMSSD；版本化参数，随时回滚 |
| 晨测和夜间 HRV 混用 | 基线偏移，分数系统性偏高或偏低 | 三种 HRV 模式分别建基线，只合成 z-score（§5.3.5） |
| Apple 睡眠分期存在误差 | 深睡 / REM 相关指标不准 | 分期只和个人基线比；在睡眠分中只占 0.15 权重；事件统计加 2 分钟阈值 |
| 自用数据量小，调参过拟合 | 分数对历史“很准”，对未来失效 | 岭回归向默认权重收缩；按时间切分验证；提升不足 0.05 不采用 |
| 数据晚到导致分数变化 | 早上看到的分数和中午不一样 | 初步 / 最终 / 锁定状态机；变化 ≥ 5 时明确标注“已更新” |
| Apple Intelligence 在当前设备或区域不可用 | 端侧教练不可用 | Claude API 兜底，或者只用模板文案 |
| 企业证书到期或吊销 | App 无法使用 | 到期提醒 + 备份；HealthKit 原始数据不受影响，可以重建 |
| HealthKit API 随系统版本变化 | 部分指标失效 | 所有查询集中在 `VigorHealth` 中；每个指标都允许缺失 |

## 附录 A：术语
- **RMSSD**：相邻 RR 间期差值的均方根，反映副交感神经活性，是 WHOOP 使用的 HRV 指标。
- **SDNN**：RR 间期的标准差，Apple 默认提供的 HRV 指标。
- **TRIMP**：训练冲量（Training Impulse），是用时长 × 强度加权得到的负荷量。
- **ACWR**：急性 / 慢性负荷比，用于判断训练量变化是否过快。
- **HRR%**：心率储备百分比。
- **MAD**：中位数绝对偏差，一种稳健的离散度度量。
- **SRI**：睡眠规律指数（Sleep Regularity Index），衡量相隔 24 小时的同一时刻处于相同睡 / 醒状态的概率。
- **WASO**：入睡后清醒时长（Wake After Sleep Onset）。
- **Shapley 值**：博弈论中的公平分配方法，这里用来把恢复分数精确拆分到每个输入分量。
- **ICC**：组内相关系数，衡量两种测量方法的一致程度。
- **Bland–Altman 分析**：比较两种测量方法的偏差和一致性界限的标准方法。
