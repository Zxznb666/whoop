## 3. Apple Watch S10 与 WHOOP 的差异，以及 noop 因此出错的地方

这是本任务的核心分析。每一条都要在 `Muse/ALGORITHM.md` 里展开，写清“noop 怎么做、为什么在 S10 上不对、我们怎么做、依据是 Vigor 的哪一节”。

| 维度 | WHOOP 手环 | Apple Watch S10（经 HealthKit） |
|---|---|---|
| 心率 | 全天约 1 Hz | 日常和睡眠约每几分钟一个点；训练中每几秒一个点 |
| HRV | 整夜逐拍 RR，算 RMSSD | 每天若干条约 1 分钟的 SDNN 记录，夜间偏多；逐拍序列存在但第三方连接器大概率拿不到 |
| 静息心率 | 从密集夜间心率推出 | Apple 给一个每日值；夜间心率稀疏 |
| 呼吸率 | 整夜 | 仅睡眠期间 |
| 皮肤/手腕温度 | 连续，直接给偏差 | 每晚一个值，偏离基线要自己算 |
| 血氧 | 夜间连续 | 间歇采样 |
| 睡眠分期 | noop 自己从加速度和心率推断 | Apple 直接给分期（清醒 / REM / 核心 / 深睡） |
| 佩戴 | 24 小时，边戴边充 | 每天要摘下充电，有未佩戴时段 |

noop 的具体问题（文件名对应 §1 的必读清单）：

1. **HRV 取的是全天平均 SDNN。** `HealthKitBridge.sync` 用 `HKStatisticsCollectionQuery` 按自然日对 `heartRateVariabilitySDNN` 取 `discreteAverage`，把白天活动状态下的读数和夜间读数混在一起，再交给 `WatchRecovery`。白天的 SDNN 受姿势和活动影响很大，会把恢复分数的主驱动项变成噪声。应改为只取主睡眠窗口内的样本，按 Vigor PRD §2.2 约束 A 的对策 3 处理：SDNN 用自己的基线，在对数域统计，不和 RMSSD 混算。
2. **手表路径丢掉了一半的输入。** `WatchRecovery.compute` 给 `RecoveryScorer.recovery` 传的 `resp`、`sleepPerf`、`skinTempDev` 都是 nil，只剩 HRV 和静息心率。而 S10 实际上有睡眠呼吸率、手腕温度、血氧和完整的睡眠分期。应全部纳入（Vigor PRD §5.5、§5.8）。
3. **静息心率的算法前提不成立。** `RecoveryScorer.restingHR` 取 5 分钟分箱均值的最小值，并要求每箱至少 5 个样本（`restingHRMinBinSamples`）。S10 睡眠时一箱通常只有 1–2 个点，没有箱子合格，算法退回到“所有箱均值的最小值”，等于取单点最低值，正是它想防的伪迹。采用 Vigor 的夜间静息心率定义（PRD §5.4，`NightRestingHR.swift`）。
4. **负荷累加假设等间隔采样。** `StrainScorer.sampleDurationMinutes` 只用前两个样本的时间差作为每个样本的时长，再乘以样本数。S10 的心率间隔从 5 秒到十几分钟不等，这样算出来的 TRIMP 没有意义。另外 `minReadings = 600` 的门槛是按 1 Hz 设计的。应按每个样本的真实时间间隔积分，空窗设上限，训练时段用高频心率（Vigor PRD §2.2 约束 B、§5.10，`Load/MinuteGrid.swift`、`LoadCalculator.swift`）。
5. **负荷量程是 0–100。** noop 把 `maxStrain` 从 21 改成了 100。本项目用 WHOOP 的 0–21，直接采用 Vigor 的 Strain 映射（`Load/Strain.swift`）。
6. **“一天”按自然日切分。** noop 的 Apple 路径按 `Calendar.current` 的自然日聚合，跨零点的睡眠和凌晨的活动会被归错。采用 Vigor 的生理周期：本次入睡到下次入睡，恢复归属于醒来的那个周期（PRD §3.1）。
7. **基线模型。** noop 用 Winsorized EWMA，冷启动要 4 晚、手表路径要 7 晚。采用 Vigor 的稳健基线：最近 30 个有效夜的中位数加 MAD，样本不足时向人群先验收缩（PRD §3.2、§5.6）。Muse 能读历史数据的话，首次建好空间就应该有可用的基线，不需要校准期。
8. **睡眠分期。** noop 的 `SleepStager` 是为没有分期数据的手环写的，这里完全不需要。直接用 Apple 的分期，界面上把“核心睡眠”显示为 WHOOP 的 Light，“深睡”显示为 SWS（Deep）。睡眠需求、睡眠债、表现、效率、规律性按 Vigor PRD §5.9。
9. **未佩戴。** WHOOP 不存在充电空窗，noop 没有处理。夜间没戴表时不出恢复分数，显示“昨晚未佩戴”；白天的未佩戴时段对负荷的贡献为 0 并在界面上标出（PRD §2.2 约束 C）。

## 4. 算法分档

Muse 给的数据粒度决定了能做到哪一步。三档都要写出完整规格和参考实现，阶段 0 的探测结果决定最后用哪一档；如果不同类型的粒度不同，可以按指标混用。

| 档 | 前提 | 恢复 | 负荷 | 睡眠 |
|---|---|---|---|---|
| A | 能读带时间戳的逐条样本 | 睡眠窗口内的 SDNN（对数域）、夜间静息心率、呼吸率、手腕温度偏差、血氧、睡眠表现，对各自的稳健基线求偏离，按 Vigor §5.8 合成 | 按真实间隔积分的 TRIMP，映射到 0–21 | Apple 分期全量指标 |
| B | 睡眠有分期时段，其他指标只有每日值 | 用每日 SDNN 和 Apple 的每日静息心率，加当晚呼吸率、温度、睡眠表现；界面标注“HRV 含日间读数” | 用训练记录（时长、平均心率）加活动能量估算，标注“估算” | 同 A |
| C | 全部只有每日汇总 | 只用每日 SDNN、静息心率、睡眠时长；标注“低精度” | 只用活动能量和训练分钟数；标注“低精度” | 只有时长和各分期总量，没有分期图 |

各档都要遵守的规则：

- **不编数**。缺主输入（当晚没有 HRV，或没有睡眠记录）就不出分数，显示原因。
- 每个分数都附带数据质量等级（高 / 中 / 低）和“数据截至 HH:MM”。
- B、C 档是 A 档的降级，公式结构保持一致，只是输入变粗；这样本地可以用同一份真实数据算出三档结果，量化降档带来的偏差。
- 公式里的每个常数都要有出处（Vigor PRD 的章节号，或 `ScoringConfig.swift` 里的字段名）。Vigor 里没有的常数，说明你的取值依据。

### 阶段 3：WHOOP 风格的设计规格与视觉样机

产出 `Muse/DESIGN.md` 和 `Muse/mock/`（单文件 HTML，读取 golden 数据渲染四个页面，手机宽度优先）。样机有两个用途：给我确认视觉，以及截图后作为参考图附给 Muse（如果探测结果显示它接受图片）。

设计要点（颜色取自 WHOOP 的品牌规范，你需要自行核对一遍）：

- 纯黑背景，深灰卡片，大号粗体窄体数字，全大写加宽字距的小标签。
- 恢复：0–33% 红 `#FF0026`，34–66% 黄 `#FFDE00`，67–100% 绿 `#16EC06`。负荷：蓝 `#0093E7`。睡眠：灰蓝 `#7BA1BB`。强调色：青绿 `#00F19F`。
- 字体：WHOOP 用 Proxima Nova 和 DIN Pro，都是商业字体。样机和提示词里指定最接近的可用替代，并说明选择。
- **概览**：顶部日期切换；三个圆环（Sleep、Recovery、Strain），中间是数值；下方是关键数据卡（HRV、静息心率、呼吸率、睡眠时长）及其相对基线的箭头。
- **恢复**：大圆环加颜色分区；贡献项列表（HRV、静息心率、呼吸率、手腕温度、血氧、睡眠表现），每项显示当日值、基线、偏离方向；近 7 天柱状图，柱子按分区着色。

- 不使用 WHOOP 的商标图形和 Logo。
- 每个数字旁边保留数据质量标记和“数据截至”时间，降档指标带上 §4 规定的标注。
