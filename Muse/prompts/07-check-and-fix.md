# 07 · 验收与修正

## 7.1 验收提示词（每做完一步、以及全部做完后用）

```
【只读，不要重算】从 VIGOR 空间保存的结果里，原样列出 {验收日}（醒来日）的下面这些字段，每个一行“字段名 = 数值”，按括号里的小数位：
wakeDay, status, recovery(2), zone, quality, hrvMs(2), hrvBaseline(2), z_hrv(3), rhr(2), rhrBaseline(2), z_rhr(3), resp(2), z_resp(3), tempDelta(3), spo2(2), z_sleep(3), strain(2), trimp(2), tstH(3), needH(3), debtH(3), performance(2), sleepScore(2)
（hrvBaseline 是 e^μ 的毫秒值；tstH、needH、debtH 是小时；还没做到的步骤写“未实现”。）
```

字段名和 `Muse/reference/golden/<数据名>/H-days.csv` 的列一一对应。核对方式有两种：

1. **用你的真实数据出标准答案（推荐）**：在 Vigor「实验室 → 导出」生成调试快照，按 `Muse/reference/README.md` 跑 `vigor-export --snapshot` 和 `node scripts/golden.js fixtures/real-latest`，得到 `golden/real-latest/H-days.csv`。参考实现会把逐条样本按 Muse 的方式聚合成小时值再计算，所以可以逐项比对。这个目录不入库。
2. **没有导出时**：把每一步 Muse 列出的中间值贴给我，我用参考实现按同样的输入复算。

**容差**：HRV、静息心率、呼吸率 ±1 个显示单位；RECOVERY ±3 且分区一致；STRAIN ±0.5；睡眠时长 ±5 分钟。另外同一天关掉空间再打开 3 次，数字必须完全一样；“未佩戴”的日子不能出现恢复分数。

注意：参考实现的小时值是自己从逐条样本聚合的，Apple 给 Muse 的小时值可能略有出入（探测时同一小时的心率平均前后读到过不同的数）。所以输入列（小时值）不一致时先对输入，再对结果。

## 7.2 修正提示词

**数字不对**（把 `{}` 换成核对结果）：

```
{验收日} 的 {字段} 你给的是 {Muse 值}，按规则应为 {标准值}。
请按“{步骤名}”的第 {k} 步重新逐步计算这一天，把每一步的中间值都列出来（包括用到的每个小时值、排序后的结果、取值的位置），找出哪一步与规则不一致，只修正那一步的做法，然后重算并保存受影响的日子。不要改动其他步骤，也不要改动其他日子的已保存结果，除非它们依赖这个值（例如基线、睡眠负债、负荷比）。
```

**每次打开数字不一样**：

```
同一天的 {字段} 三次打开分别是 {a}、{b}、{c}。请不要在打开时重新计算历史日子：只读取已保存的结果；只有出现新的醒来日、或者重新读取的输入和保存的不一样时，才重算那一天和依赖它的后续日子。改完后告诉我结果保存在哪里、什么时候会被写入。
```

**视觉不对**：

```
【只改外观，不改数字】{页面} 的 {组件} 现在是 {现状}，应该是 {DESIGN.md 里对应的描述，带色值和几何}。只改这一处。
```
