# 三档算法对照报告（合成数据）

> 生成：`node scripts/compare.js`（数据：`fixtures/synthetic-seed42`，即 Vigor 黄金快照用的同一份合成场景，seed 42，120 晚）。
> 对照基准：Vigor 完整管线（逐拍 RMSSD），由 `vigor-export` 只读调用 `Packages/VigorScoring` 生成。
> **以下结论全部来自合成数据，尚未用你的真实数据验证。** 真实数据的做法见 `README.md`“用真实数据验证”。

## 结论先说

1. **算法移植是对的。** A 档的睡眠时长、效率、SRI、呼吸率、温度偏差、血氧与 Vigor 逐晚一致（差 ≤ 0.01）；把 HRV 输入换成 Vigor 的 z_hrv 后，恢复分数平均差 0.73 分、分区一致率 96.6%，剩下的差别来自静息心率（Vigor 多用了逐拍序列的平均心率）和负荷（下面第 4 条）。
2. **恢复分数的偏差几乎全部来自 HRV 输入**（Muse 只能拿 SDNN，Vigor 用逐拍 RMSSD）。Vigor 的合成数据里 SDNN 是独立抽取的随机数，和 RMSSD 的相关系数只有 0.15，这不符合生理，所以第一张表的恢复偏差（MAE 约 17、分区一致率约 45%）是**悲观上限**，不代表真实情况。
3. 在“夜间 SDNN 与 RMSSD 相关（r ≈ 0.8）”的**假设**下（第三张表），A 档恢复 MAE 5.8、分区一致率 82%；B 档（全天平均 SDNN）MAE 9.6、一致率 69%；C 档 MAE 10.0、一致率 66%。A → B 的退化主要来自日间 SDNN 混入，这正是 noop 缺陷 1 的量化。
4. **负荷**：A 档对 Vigor 的平均差 0.45、最大差 7.6。最大差出现在 Vigor 有 FIT 导入骑行（逐秒心率和功率补偿）的日子，Muse 读不到这些；去掉 FIT 后（逐项表）Strain 平均差 0.02、最大差 0.12。B/C 档负荷是估算，平均差 3–3.7，非训练部分的常数（M-06）需要用真实数据校准。
5. **睡眠**：三档睡眠时长与 Vigor 一致。B/C 档的睡眠分和 Performance 有 2–4 分的差，来自负荷估算误差通过“负荷追加”传到睡眠需求。

## 各列含义

- **恢复 MAE**：同一醒来日，本档恢复分数与 Vigor 恢复分数之差的绝对值的平均（百分点）。
- **分区一致率**：两边都出分的日子里，红/黄/绿分区相同的比例。
- **相关系数**：恢复分数的 Pearson 相关。
- **A，HRV 换成 Vigor 的 z_hrv**：A 档其余输入不变，只把 z_hrv 换成 Vigor 的值，用来隔离“HRV 输入不同”以外的偏差。
- **差 ≤ 0.01 的天数**：逐项表里，与 Vigor 相差不超过 0.01 的晚数（睡眠需求、负债的小差异是负荷差异经“负荷追加”传过来的）。

## 合成数据的局限（如实说明）

- SDNN 与 RMSSD 无关（见上）；白天心率 65–95 bpm 偏高，使非训练负荷偏大；没有日间 SDNN（第二、三张表是按规则补的）。
- 合成数据没有呼吸紊乱样本，“呼吸紊乱升高”扣分项没有被覆盖到。
- 所以：**偏差大小以真实数据为准**；合成数据只证明“公式移植正确”和“三档降级的方向与相对大小”。
